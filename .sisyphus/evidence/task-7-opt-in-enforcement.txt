Enforcement Strategy:
=====================

1. SQL-Level Enforcement (Primary Defense):
   Query filters at database level:
   
   const { data: creators } = await supabase
     .from('creator_profiles')
     .select('creator_id, news_topics, news_cadence, context_opt_in, news_enabled, updated_at')
     .eq('context_opt_in', true)      // ← FIRST GATE
     .eq('news_enabled', true)        // ← SECOND GATE
     .limit(maxCreators);

   Result: Ineligible creators NEVER enter processing pipeline

2. Application-Level Enforcement (Defense in Depth):
   Double-check within fetchNewsForCreator():
   
   if (!creator.context_opt_in || !creator.news_enabled) {
     return {
       creator_id: creator.creator_id,
       success: true,
       topics_updated: 0,
     };
   }

   Result: Even if SQL filter fails, app layer blocks

3. Cadence-Based Rate Limiting (Efficiency):
   Before fetch, check last_fetched_at:
   
   const cadenceWindow = getCadenceWindow(creator.news_cadence);
   // hourly → 1 hour ago, daily → 1 day ago, weekly → 7 days ago
   
   if (lastFetch > cadenceWindow) {
     return; // Already fetched within window
   }

   Result: No redundant API calls, respects creator preferences

async function checkOptIn(supabase, creatorId) {
  const { data } = await supabase
    .from('creator_profiles')
    .select('context_opt_in')
    .eq('creator_id', creatorId)
    .maybeSingle();
  return data?.context_opt_in === true;
}
